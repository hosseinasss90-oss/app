# معیار پذیرش — حسابینو v1

## AC-1 ثبت دستی ≤ ۲ تعامل
- از خانه یا تراکنش‌ها، FAB مسیر طلایی را باز می‌کند.
- مبلغ فوکوس است؛ نوع=هزینه؛ دسته و حساب از آخرین انتخاب پر شده‌اند.
- تعامل ۱: وارد کردن مبلغ. تعامل ۲: ذخیره.
- پس از ذخیره، بازگشت + Snackbar.

**تست دستی:** نصب روی دستگاه → + → ۱۲۰۰۰۰ → ذخیره → ردیف «خوراک −۱۲۰٬۰۰۰ ت» دیده شود.

## AC-2 SMS → BankEvent
- با دسترسی READ/RECEIVE_SMS، پیامک بانکی لحظه‌ای BankEvent می‌سازد.
- اسکن اولیه inbox از تنظیمات، همان مسیر ingest را صدا می‌زند.
- مبلغ فارسی/لاتین، ریال/تومان، ۴ رقم کارت استخراج می‌شود.
- اگر parse نشود، event با وضعیت UNPARSED ذخیره می‌شود.

**تست:** ارسال/داشتن SMS نمونه ملت با «مبلغ: 1,200,000 ریال» → در پیش‌نویس‌ها ظاهر شود.

## AC-3 ساخت قانون از نمونه
- از جزئیات تراکنش: «ساخت قانون از این تراکنش».
- از پیش‌نویس SMS: ویرایش → Rule Builder با sender/مبلغ/عنوان پر شده.
- هشدار اگر فقط شرط مبلغ باشد.
- Dry-run روی پیام‌های اخیر بدون persist.

**تست:** تراکنش تن ماهی → ساخت قانون → مبلغ ۱۲۰۰۰۰ + فرستنده BMJI → ذخیره.

## AC-4 اجرای قانون
- Match + autoApprove → Transaction با `createdFrom=SMS_RULE`.
- Match + draft → Draft PENDING؛ تأیید یک‌تپ → Transaction `SMS_DRAFT`.
- No match → Draft پیشنهادی (تنظیم پیش‌فرض).
- چند قانون هم‌اولویت → Draft با یادداشت تداخل.

**تست:** قانون تن ماهی (draft) + SMS 1,200,000 ریال ملت → پیش‌نویس «تن ماهی» → تأیید → در لیست تراکنش.

## AC-5 عدم ثبت تکراری
- Restart اپ، SMS دوباره deliver نمی‌شود؛ داده باقی است.
- Re-import inbox: fingerprint UNIQUE → insert نادیده.
- تغییر خط مانده، همان دقیقه، همان مبلغ → یک event.

**تست واحد:** `FingerprintTest` و `RuleEngineTest`.
**تست دستی:** اسکن دوباره inbox → تعداد BankEvent ثابت.

## AC-6 UX اجباری
- RTL کامل، فارسی، تاریخ شمسی در لیست و داشبورد.
- Dark Mode از سیستم.
- تومان/ریال قابل تغییر؛ جداکننده هزارگان.
- حالت خصوصی ارقام را `••••` می‌کند.
- قفل PIN (و بیومتریک در تنظیمات).

## AC-7 امنیت
- بدون شبکه پیش‌فرض.
- متن خام SMS پیش‌فرض ذخیره نمی‌شود.
- PIN به صورت salt+SHA-256.
- Backup ابری سیستم‌عامل خاموش است.
